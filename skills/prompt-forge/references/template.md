# 프롬프트 템플릿

해당 없는 섹션은 뺀다. 작은 작업이면 목표, 요구사항, 완료 기준만으로 충분하다.

```markdown
# [작업 제목]

## 목표
[무엇을 왜 하는지 1~3문장. 방법이 아니라 얻으려는 결과 중심]

## 맥락
- 스택: [프레임워크, 버전 등 코드에서 확인한 것]
- 관련 코드: `경로` — [역할 한 줄]
- 참고할 기존 패턴: `경로` — [어떤 점을 따를지]

## 범위
- 포함: [...]
- 제외: [이번에 하지 않을 것, 건드리지 말 파일]

## 요구사항
1. [검증 가능한 구체적 동작]
2. ...

## 결정 사항
- [결정] — 이유: [왜]

## 엣지 케이스와 예상 문제
- [상황] → [기대 동작 또는 대응]

## 제약
- [라이브러리 추가 금지, 기존 API 시그니처 유지 등]

## 완료 기준
- [ ] [실행할 명령과 기대 결과]
- [ ] [수동 확인 시나리오]

## 진행 방식
- [작업 순서가 중요하면 단계]
- 다음 상황에서는 멈추고 확인을 받을 것: [...]

## 가정 (확인 안 된 기본값)
- [가정] — 다르면 알려줄 것
```
