# --browsers / --devices 환경 매트릭스

같은 시나리오를 여러 브라우저·기기 에뮬레이션에서 돌려 특정 환경에서만 깨지는 것을 찾는다. 실기기가 아니다 — WebKit은 iOS Safari와 다르다(실제 키보드, 주소창, 렌더링 차이는 못 본다). 리포트에 이 한계를 한 줄 적는다.

## 환경 구성

- 환경 = 브라우저 × 기기. 한 축만 주면 다른 축은 기본값(chromium, 데스크톱 1280x720).
- 기기는 맞는 엔진으로 연다: iPhone/iPad → webkit, Android → chromium(`--browsers`에 없어도 기기 우선).
- **기준 환경** = chromium 데스크톱. 여기서 진단을 끝내 plan.md를 확정한 뒤, 나머지 환경은 그 plan.md를 재생한다.
- 환경마다 세션 분리: `playwright-cli -s=<환경 이름> open --browser <엔진> [--device "<기기>"] <url>`. 엔진이 없으면 `playwright-cli install-browser <엔진>`.
- 로그인은 기준 환경의 `auth.json`을 `state-load`로 재사용.

## 실행 범위

환경 N개면 시간도 N배이므로:

- 기준 환경: plan.md 전체
- 나머지: `[변경]` 시나리오 + 각 화면 첫 진입(레이아웃 확인). `all` 모드면 `[핵심]` 시나리오.
- 사용자가 전체를 원하면(예: "전 환경 전체로") 모든 시나리오.

## 환경별 추가 확인

동작 결과가 기준 환경과 같은지에 더해, 화면 진입마다:

- **가로 넘침**: `eval "() => document.documentElement.scrollWidth > document.documentElement.clientWidth"`가 true면 넘치는 요소를 찾아 기록.
- **스크린샷**: `screenshot --filename="$RUN_DIR/<환경>/<화면>.png"`를 기준 환경 스크린샷과 눈으로 대조해 겹침·잘림·사라진 요소를 찾는다.
- **모바일**: 반응형 전환(햄버거 메뉴 등)이 열리고 동작하는지, 주요 터치 대상이 24x24px 미만인지(`eval`로 boundingClientRect), 고정 헤더·하단 바가 콘텐츠를 가리는지.
- **브라우저별 기능 차이**(diff에 해당 기능이 있을 때): `<input type="date">`, 클립보드, 파일 업로드, `:has()` 같은 최신 CSS, 스크롤 스냅, 스무스 스크롤, 날짜 파싱(`new Date('2026-01-01 10:00')`처럼 엔진마다 다른 형식).

## 판정

- 기준 환경과 동작 결과가 다름 → 실패(환경 한정 회귀)
- 레이아웃 깨짐(넘침, 겹침, 잘림, 조작 불가) → 실패
- 폰트 렌더링·안티앨리어싱 같은 엔진 고유의 미세 차이 → 무시
- 기준 환경에서도 실패 → 환경 문제가 아니므로 기준 환경 결과로만 보고

## 리포트

실패 항목에 환경을 명시하고(`❌ /cart — 수량 증가 [webkit · iPhone 15]`), 통과 표 아래에 매트릭스 요약을 붙인다:

```markdown
## 🌐 환경 매트릭스 (에뮬레이션 — 실기기 아님)
| 시나리오 | chromium | firefox | webkit | iPhone 15 | Pixel 7 |
|---|---|---|---|---|---|
| /cart S1 수량 증가 | ✅ | ✅ | ❌ | ❌ | ✅ |
| /cart 레이아웃 | ✅ | ✅ | ✅ | ⚠️ 가로 넘침 | ✅ |
```
